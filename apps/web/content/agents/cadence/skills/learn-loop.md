# Learn Loop

Post-ship and post-incident learning that does not become theater.

## When to use

- After incidents, failed deploys, or surprising metrics
- Sprint / weekly engineering retros
- Turning a near-miss into a permanent control

## Loop steps

1. **Facts first** — timeline, impact, detection
2. **Contributing factors** — systems, not villains
3. **What we believed that was wrong**
4. **One experiment** (hypothesis + metric + window)
5. **Owner + due date**
6. **Close the loop** next cadence with result

## Anti-patterns

- Action lists with no owners
- Blameless in name only
- Ten actions; zero completion
- Skipping customer impact

## Output contract

```markdown
## Learn Loop — YYYY-MM-DD
**Event:** ...
**Impact:** ...

### Timeline
...

### Insights
1. ...

### Experiment
- Hypothesis:
- Metric:
- Window:
- Owner:
```
